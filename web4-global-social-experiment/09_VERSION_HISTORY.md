Purpose

The Version History documents every meaningful change made to the Global Social Experiment repository.

It answers:

“What changed, when did it change, why did it change, and what evidence justified the change?”

Unlike a traditional software changelog, this repository tracks:

* research evolution;
* theoretical refinement;
* governance revisions;
* legal corrections;
* methodological improvements;
* evidence updates;
* AI-review outcomes;
* publication synchronization;
* and implementation maturity.

Nothing of scholarly significance should change silently.

⸻

Version Numbering

The repository follows semantic versioning adapted for research.

MAJOR.MINOR.PATCH

Example

1.0.0
1.1.0
1.2.3
2.0.0

⸻

Major Release

Increase MAJOR when:

* repository architecture changes;
* research methodology changes significantly;
* canonical theory changes;
* breaking governance changes occur;
* or major legal revisions require widespread updates.

⸻

Minor Release

Increase MINOR when:

* new research questions are added;
* new case studies are introduced;
* new educational modules appear;
* additional implementation guidance is added;
* or new publication mappings are created.

⸻

Patch Release

Increase PATCH when:

* typographical errors are corrected;
* citations improve;
* formatting changes;
* metadata updates;
* clarification wording;
* non-breaking legal updates;
* or documentation corrections.

Breaking Changes

Breaking changes require additional documentation.

Examples include:

* changing required consent fields;
* modifying identity definitions;
* altering repository architecture;
* changing governance hierarchy;
* replacing canonical terminology;
* restructuring question identifiers.

Breaking changes require:

* migration notes;
* compatibility statement;
* publication review;
* website update;
* and repository announcement.
