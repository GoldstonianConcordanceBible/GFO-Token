1. Purpose

This file is the master index for all research, governance, methodology, evidence, policy, technical, publication, licensing, and prompt-backend materials contained within the web4-global-social-experiment folder.

It provides:

* the authoritative document sequence;
* the purpose of each file;
* the status of each repository domain;
* dependencies between documents;
* canonical and noncanonical classifications;
* publication mappings;
* prompt-retrieval mappings;
* and the order in which contributors, reviewers, developers, and website users should interpret the repository.

This index must be updated whenever:

* a canonical file is added;
* a canonical file is renamed;
* a major directory is added;
* a file becomes deprecated or superseded;
* a document dependency changes;
* a new public release is issued;
* or a new derivative publication is mapped to the repository.

⸻

2. Authority Order

When repository materials conflict, apply the following authority order:

1. applicable law, binding agreements, and controlling entity documents;
2. parent GFO-token governance and security requirements;
3. 00_REPOSITORY_CHARTER.md;
4. approved standards and governance policies;
5. approved technical specifications and controls;
6. release-specific implementation documentation;
7. verified research findings;
8. Delphi consensus findings;
9. reviewed research material;
10. hypotheses, interpretations, and future research;
11. archived, superseded, or withdrawn content.

A higher-ranked source does not automatically make a claim factually correct. Claims must still satisfy evidence, verification, and review requirements.

6. Prompt Retrieval Priority

The backend should retrieve in the following order:

1. approved policies and standards;
2. verified facts and verified legal claims;
3. approved research findings;
4. Delphi consensus with limitations;
5. contested findings with dissent;
6. research questions;
7. hypotheses and interpretations;
8. archived material only when explicitly requested.

For high-risk questions, retrieval must also include:

* limitations;
* legal-review status;
* jurisdiction;
* source freshness;
* and activation-readiness status.

8. Canonical Versus Derivative Content

Canonical

Content that defines the current approved state of:

* research questions;
* methodology;
* governance;
* standards;
* evidence;
* schemas;
* policies;
* technical requirements;
* and release status.

Derivative

Content generated from canonical sources for:

* books;
* articles;
* presentations;
* website answers;
* reports;
* training;
* consulting;
* or public communication.

Source Material

Raw content used to develop canonical material, including:

* conversations;
* transcripts;
* interviews;
* model outputs;
* public posts;
* notes;
* recordings;
* and imported documents.

Source material is not automatically canonical.

11. Index Maintenance Rule

Every structural pull request must answer:

1. Does this change add, remove, rename, or supersede a canonical file?
2. Does the canonical index require revision?
3. Does the change alter document authority?
4. Does the change create a new dependency?
5. Does the change affect prompt retrieval?
6. Does the change affect public website labels?
7. Does the change require a version increment?
8. Does the change affect a book, article, conference, or licensing output?
9. Does the change require legal, privacy, security, or technical review?
10. Does the change create scope drift?

A structural change is incomplete until this index is updated.
